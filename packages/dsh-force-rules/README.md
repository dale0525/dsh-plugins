# dsh-force-rules — DSH 规则门禁

> 为 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）提供的规则门禁插件：把「禁用一次性子代理」「派单后不空转」「沉默必须有上限」「席位只拿到指令授权的权限」「交付前说人话」五条规范从**散文**变成**确定性机制**（前四条是硬门禁，第五条是轮次结束时的必定提醒）

**🌏 中文**

`dsh` · `dsh-plugin` · `plugin` · `subagent` · `delegation` · `rules` · `guard` · `派单` · `子代理` · `检查点`

## 简介

规范写在 `AGENTS.md` 里只是**建议**：模型可以不遵守，而且这几条各自都真实翻过车。

| 规范 | 光靠散文的后果 |
|---|---|
| 禁用一次性子代理 | `run_in_background: false` 是进入一次性路径的**唯一开关**，返回的 `runId` 无法用 `send_message` 续期，结算也不会通知派单方 —— 派单方只能同步阻塞到执行上限 |
| 派单后不空转 | Root 反复查询状态或自造 sleep 陪跑，属无谓空转 |
| 沉默必须有上限 | 席位异常死掉、`subagent/end` 永不触发时，派单方**永远等不到** |
| 席位默认只读 | 派单指令里写着「只读」，子代理照样能 `write`、`git push`、发版 —— 授权范围只活在散文里，没有任何东西在拦 |
| 交付前说人话 | 「说人话」「当普通用户」只写在技能文件里，回答发出去之前没有任何东西把它拿到模型眼前 |

本插件把这些规范落成四层机制（前四条是硬门禁，第五条是必定送达的提醒）：

- **前两条规范 → 派单前拒绝**。挂在 `tools/pre-execute` 上，在工具体执行**之前**就把 `run_in_background: false` 挡回去。这也覆盖 `run_code` 里的 `tools.subagent(...)` 子派发 —— 它走的是同一条策略流水线。
- **第三条规范 → 自唤醒检查点**。席位一启动就在派单方会话上登记一个 **10 分钟**的持久化检查点；席位正常结算就把它删掉，静默死掉就由它到点唤醒。**沉默因此有了上限。**
- **第四条规范 → 按指令授权的权限档案**。派单指令开头的标记决定席位能调哪些工具，逐次调用在 `tools/pre-execute` 上校验。该要求同时被追加到派单工具**自己的描述**上（见下节）。
- **第五条规范 → 轮次结束时的说人话提醒**。插件监听 `agent/turn-stopping`：根会话的轮次即将关闭、回答即将交付的那一刻，把六条说人话规范 steer 回模型，让它带着规范再走一步（见「说人话提醒」节）。

## 怎么识别「派单工具」

不能按工具名硬编码，也不能只看 `run_in_background` 这个参数名：`bash`、`pwsh`、`workflow` **也**声明了这个参数，但它们根本产生不了席位。

判据取工具**自己的输出声明**：只有派单工具的输出 schema 里带 `{ const: 'continuable' }` 这个分支。本插件递归扫描 `ctx.tools.get(name).output.schema`，命中才拦。

| 工具 | 有 `run_in_background` | 输出声明 `continuable` | 是否拦截 |
|---|---|---|---|
| `subagent` / `subagent_fork` | 是 | 是 | **拦截 + 描述追加标记要求** |
| `bash` / `pwsh` / `workflow` | 是 | 否 | 放行 |
| 未注册工具 | — | — | 放行 |

同一个判据还用于**把标记要求写进派单工具的描述**：插件挂在 `system-prompt/assemble` 上，在装配时给每个判为派单工具的 schema 追加一段说明。理由很直接——Root 读不到规则就守不住规则；这条要求原先只写在 `AGENTS.md` 与 `delivery-discipline` 技能里，仍被漏掉过（席位拿到散文形式的工具白名单、没写标记，被静默降为只读，直到一整轮后才在某个被拒的步骤上暴露）。工具描述是模型**决定派单那一刻**唯一在眼前的位置。只改 `description`，只改派单工具。

## 行为

```
派单（continuable）  →  subagent/start  →  清旧检查点 + 登记 10 分钟检查点
                                            ↓
                          席位结算（subagent/end）
                                            ↓
                    还有别的席位在跑？ ── 是 ──→ 保留检查点
                                            └─ 否 ──→ 删除检查点
```

检查点在派单方会话上**最多只有一个**：新席位启动时先删旧的再建新的，所以不会醒来时堆一串重复任务。续期逻辑按**标题**查找而不是记在内存里，因此重启后依然成立 —— 而重启恰恰是旧检查点会和新检查点叠加的时刻。

## 派单授权档案

写一个标记，席位就只拿到这个档案允许的工具。**不写标记 = 只读**。

| 标记 | 席位可以做什么 |
|---|---|
| （无标记） | 只读：读文件、检索、联网查资料、回报结论 |
| `[只读]` | 同上（显式写法） |
| `[审核]` | 只读 **+** 只读命令（`git status/diff/log`、`ls`、`cat`、`grep`、`terraform plan`、`kubectl get` …） |
| `[编辑: src/a.js, src/b.js]` | 只读 **+** 只写这几个文件 |

英文拼写 `[readonly]` / `[review]` / `[edit: …]` 等价。

**标记必须开在指令最前面。** 前导空白（换行、缩进）容忍，但标记之前出现任何其它文字，标记就**失效**，该席位退回只读。

| 写法 | 实际结果 |
|---|---|
| `[编辑: src/a.js] 修掉这个 bug` | 编辑档案（正确写法） |
| `\n\n  [编辑: src/a.js] …` | 编辑档案（前导空白容忍） |
| `先看这里。\n[编辑: src/a.js] 修它` | **只读** —— 标记前有文字，失效 |
| 只读指令里**提到**标记：「不要用 `[编辑: src/a.js]`」 | **只读** —— 引用不再提权（旧版会提权） |

**为什么必须锚定开头**：插件若扫描整条指令去找标记，一份只读简报只要**引用**了标记就会被提权成它本来要禁止的档案——「不要用 `[编辑: src/a.js]`」真的让那个席位能写 `src/a.js`（旧版实测）。锚定开头让引用变成惰性的，同时让「哪个标记生效」不再有歧义：只有最前面那一个。

**因此不要在指令开头引用标记本身。** 要解释规则，把说明写在标记**之后**，或**去掉方括号**（写成 `编辑: <路径>`）。

**只读档案是白名单，不是黑名单**：只有名单里的工具能用，其余一律拒绝。黑名单会让宿主以后新增的写工具被**默认放行**，而那正是这个档案要防的事。

**审核档案额外禁用 shell 连接符**（`;`、`&&`、`|`、`>`、`$()`、反引号）。只白名单首个命令词是不够的：`git status && rm -rf build` 和 `git log | sh` 都以合法命令开头。只允许**单条、无连接**的只读命令。

**编辑档案按路径后缀比对**，所以 `src/a.js`、`./src/a.js` 与绝对路径都能匹配。它是防止席位跑偏出切片的**护栏**，不是文件系统沙箱。

**PTC 模式不受影响**：`run_code` 对所有档案都放行（它是席位调用其它工具的唯一通道），但它**子派发**出去的每一次调用，走的还是同一条策略流水线，按同一个档案校验。

档案在席位启动时读一次并缓存 —— 指令在席位存活期间不会变。**Root 会话不受任何限制**：它没有派单方，本插件只约束席位。

## 说人话提醒

「说人话」「把用户当做不懂技术的普通用户」这类要求原先只活在技能文件里。技能是**按需加载**的：模型不加载它，规则就不在眼前，回答照发。

这里刻意**不做成工具**。工具是被**模型主动调用**的——模型不调，它就不存在，所以它天然盖不住「轮次即将结束」这个时刻。能盖住这个时刻的是**轮次边界本身**：宿主在轮次即将关闭、且模型不再欠任何回复时派发 `agent/turn-stopping`，并**等它跑完才提交边界**。在这个监听器里 `steer`，模型就会带着规范再走一步。

| | 做成工具 | 挂在轮次边界 |
|---|---|---|
| 谁决定它发生 | 模型（可能不调） | 宿主（必定派发） |
| 能否覆盖「回答即将发出」 | 不能 | 能 |
| 同一轮会重复触发吗 | 调几次算几次 | 一轮一次，由会话 id + 轮次号去重 |

**它只提醒，不检查。** 这是刻意的：「够不够通俗」没有可计算的答案，而 `validate_dsh_ui` 有效是因为它手里有硬判据（括号配对、字段名）。没有判据的「校验」只会是假装。steer 进去的是**规范正文**——六条要求，来自 `wait-what` 技能：写大白话、补齐读者缺的前提、代码与命令原样保留、用 `CONTEXT.md` 的词汇、不趁机改结论或扩大范围、只有更清楚之后才允许更短。

**只对根会话生效。** 席位是向派单方汇报，fork 出来的延续是向调用方汇报，两者的回答都不由用户阅读，因此都不发这条提醒。判据是「这个会话没有派单方」（`header.parentSession` 不存在，且不是席位）。

**为什么需要去重**：steer 会让模型再走一步，而这一步结束时会**再次**走到轮次边界。不去重就是无限循环。守卫按「会话 + 轮次号」记一个数，轮次号在一轮内是固定的、跨轮单调上升，所以同一轮只提醒一次，下一轮照常提醒；会话销毁时清掉。

> **诚实边界**：这套机制做到的是「在正确的时刻、必定把规范送到模型眼前」，**不是**「保证模型照做」。它比工具调用强得多（不依赖模型主动），但仍不是校验器——「够不够通俗」没有可计算的失败判据。

## 它不做什么

- **不替你派单**，也不改写派单内容（`prompt` 原样传给席位）；只往派单工具的描述上追加标记要求。
- **不检查席位是否真的还活着**：它只保证「沉默到点会唤醒你」，到点之后查 `list_agents` 并作判断是**你**的事。检查点唤醒的提示文本里写了这一步。
- **不管 `maxDepth`、模型选择**等其他派单规范。
- **不在 `subagent/end` 上做补救**：那是结算之后才触发的水位线，拦不住已经发生的派单。本插件只做「事前拒绝」与「到点唤醒」。
- **不检查回答是否真的通俗**：说人话提醒只把规范放到回答之前，它算不出「够不够通俗」，也拦不住任何回答。

## 配置

**无配置。** 10 分钟的界限、这条禁令与三档授权档案本身就是它存在的理由，所以是源码里的常量，而不是可能和规则漂移的设置项。

## 安装

随聚合包 `@logictan/dsh-plugins-all` 一起安装；单独安装时该包声明 `dsh.bundle.patch`，由 `dsh plugin add` 加载。
