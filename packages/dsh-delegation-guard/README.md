# dsh-delegation-guard — DSH 派单守护

> 为 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）提供的派单守护插件：把「禁用一次性子代理」「派单后不空转」「沉默必须有上限」「席位只拿到指令授权的权限」四条规范从**散文**变成**确定性硬门禁**

**🌏 中文**

`dsh` · `dsh-plugin` · `plugin` · `subagent` · `delegation` · `guard` · `派单` · `子代理` · `检查点`

## 简介

规范写在 `AGENTS.md` 里只是**建议**：模型可以不遵守，而且这几条各自都真实翻过车。

| 规范 | 光靠散文的后果 |
|---|---|
| 禁用一次性子代理 | `run_in_background: false` 是进入一次性路径的**唯一开关**，返回的 `runId` 无法用 `send_message` 续期，结算也不会通知派单方 —— 派单方只能同步阻塞到执行上限 |
| 派单后不空转 | Root 反复查询状态或自造 sleep 陪跑，属无谓空转 |
| 沉默必须有上限 | 席位异常死掉、`subagent/end` 永不触发时，派单方**永远等不到** |
| 席位默认只读 | 派单指令里写着「只读」，子代理照样能 `write`、`git push`、发版 —— 授权范围只活在散文里，没有任何东西在拦 |

本插件把这些规范落成三层机制：

- **前两条规范 → 派单前拒绝**。挂在 `tools/pre-execute` 上，在工具体执行**之前**就把 `run_in_background: false` 挡回去。这也覆盖 `run_code` 里的 `tools.subagent(...)` 子派发 —— 它走的是同一条策略流水线。
- **第三条规范 → 自唤醒检查点**。席位一启动就在派单方会话上登记一个 **10 分钟**的持久化检查点；席位正常结算就把它删掉，静默死掉就由它到点唤醒。**沉默因此有了上限。**
- **第四条规范 → 按指令授权的权限档案**。派单指令开头的标记决定席位能调哪些工具，逐次调用在 `tools/pre-execute` 上校验。详见下节。

## 怎么识别「派单工具」

不能按工具名硬编码，也不能只看 `run_in_background` 这个参数名：`bash`、`pwsh`、`workflow` **也**声明了这个参数，但它们根本产生不了席位。

判据取工具**自己的输出声明**：只有派单工具的输出 schema 里带 `{ const: 'continuable' }` 这个分支。本插件递归扫描 `ctx.tools.get(name).output.schema`，命中才拦。

| 工具 | 有 `run_in_background` | 输出声明 `continuable` | 是否拦截 |
|---|---|---|---|
| `subagent` / `subagent_fork` | 是 | 是 | **拦截** |
| `bash` / `pwsh` / `workflow` | 是 | 否 | 放行 |
| 未注册工具 | — | — | 放行 |

## 行为

```
派单（continuable）  →  subagent/start  →  清旧检查点 + 登记 10 分钟检查点
                                            ↓
                          席位结算（subagent/end）
                                            ↓
                    还有别的席位在跑？ ── 是 ──→ 保留检查点
                                            └─ 否 ──→ 删除检查点
```

检查点在派单方会话上**最多只有一个**：新席位启动时先删旧的再建新的，所以不会醒来时堆一串重复任务。续期逻辑按**标题**查找而不是记在内存里，因此重启后依然成立 —— 而重启恰恰是旧检查点会和新检查点叠加的时刻。

## 派单授权档案

派单指令的**开头**写一个标记，席位就只拿到这个档案允许的工具。**不写标记 = 只读**。

| 标记 | 席位可以做什么 |
|---|---|
| （无标记） | 只读：读文件、检索、联网查资料、回报结论 |
| `[只读]` | 同上（显式写法） |
| `[审核]` | 只读 **+** 只读命令（`git status/diff/log`、`ls`、`cat`、`grep`、`terraform plan`、`kubectl get` …） |
| `[编辑: src/a.js, src/b.js]` | 只读 **+** 只写这几个文件 |

英文拼写 `[readonly]` / `[review]` / `[edit: …]` 等价。

**只读档案是白名单，不是黑名单**：只有名单里的工具能用，其余一律拒绝。黑名单会让宿主以后新增的写工具被**默认放行**，而那正是这个档案要防的事。

**审核档案额外禁用 shell 连接符**（`;`、`&&`、`|`、`>`、`$()`、反引号）。只白名单首个命令词是不够的：`git status && rm -rf build` 和 `git log | sh` 都以合法命令开头。只允许**单条、无连接**的只读命令。

**编辑档案按路径后缀比对**，所以 `src/a.js`、`./src/a.js` 与绝对路径都能匹配。它是防止席位跑偏出切片的**护栏**，不是文件系统沙箱。

**PTC 模式不受影响**：`run_code` 对所有档案都放行（它是席位调用其它工具的唯一通道），但它**子派发**出去的每一次调用，走的还是同一条策略流水线，按同一个档案校验。

档案在席位启动时读一次并缓存 —— 指令在席位存活期间不会变。**Root 会话不受任何限制**：它没有派单方，本插件只约束席位。

## 它不做什么

- **不替你派单**，也不改写派单内容。
- **不检查席位是否真的还活着**：它只保证「沉默到点会唤醒你」，到点之后查 `list_agents` 并作判断是**你**的事。检查点唤醒的提示文本里写了这一步。
- **不管 `maxDepth`、模型选择**等其他派单规范。
- **不在 `subagent/end` 上做补救**：那是结算之后才触发的水位线，拦不住已经发生的派单。本插件只做「事前拒绝」与「到点唤醒」。

## 配置

**无配置。** 10 分钟的界限、这条禁令与三档授权档案本身就是它存在的理由，所以是源码里的常量，而不是可能和规则漂移的设置项。

## 安装

随聚合包 `@logictan/dsh-plugins-all` 一起安装；单独安装时该包声明 `dsh.bundle.patch`，由 `dsh plugin add` 加载。

## 开发

```bash
pnpm test          # node --test（29 个用例，覆盖四条规范、三类误报与三档授权档案）
node build.mjs     # src/ → lib/（prepare / prepack 也会跑）
```
