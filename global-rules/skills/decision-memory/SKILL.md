# 决策记忆

正文格式、召回与常规记忆操作遵循 `openviking-memory` 技能，本技能只规定架构决策记忆的**触发判据、落点与推翻规则**。

## 触发判据（两条全满足才写）

1. **改动落在系统骨架**：跨子系统契约、运行时进程／拓扑模型、持久化或存储选型、全局不变量。
1. **能当场指名被否掉的候选方案及其原因**：仅靠「改动很大」「重构了机制」「跨多个文件」不构成触发理由。

日常进度、一次性排查、常规对话由会话提交后的自动抽取覆盖，不主动镜像成记忆。

## 写入与归属

- **核心内容**：正文必须写清**选定方案、被否掉的候选方案及否定原因**，防止后续会话把已否方案当新方案重提。扁平单层，严禁维护总索引。
- **通过 `mcp__openviking__remember` 提交**：在目标项目会话内调用 `mcp__openviking__remember`，由 OpenViking 服务端按当前会话 peer（Git `origin`、`.openviking/config.json` 或 `OPENVIKING_PEER_ID`）自动归档到对应仓库记忆空间并建索引；仅跨仓库通用结论才在无 peer 会话归入用户级。
- **不在目标仓库会话内时**：按 `openviking-memory` 约定在内容前缀显式标注 `<project>: …`，或切换到目标仓库会话／为目录建 `.openviking/config.json`，**禁止**试图用 `mcp__openviking__write` 直接往只读管理子树（`peers/`、`skills/`、`privacy/`、`sessions/`）强写或硬编码账号路径。
- **严禁非法路径**：使用任何 URI 写入或编辑操作时，禁止构造父级以 `.md` 结尾的路径（如 `foo.md/bar.md`）。

## 推翻既有结论

- **只新增不篡改**：绝不直接删除或改写旧记忆的原结论正文。
- **旧件加失效指针**：用 `mcp__openviking__edit`（保留元数据并刷新索引）在旧记忆顶部或尾部追加一行指向新结论的失效说明，原正文不动。
- **新件写清因果**：通过 `mcp__openviking__remember` 记录新结论、旧结论失效的原因与替代关系，并用 `mcp__openviking__read` 核验旧件指针更新完整。
