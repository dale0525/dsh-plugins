# 收尾与提交

**只在用户显式说出「提交吧」「推送」「收尾」「合并分支」或主动调用本技能时执行**；未要求绝不碰 Git。

## 前置检查

- 不是 Git 仓库就直接说明并停止。
- 记下当前分支，判断是否在 linked worktree 中：`git rev-parse --git-dir` 与 `git rev-parse --git-common-dir` 输出不同即为 linked worktree（路径取 `git rev-parse --show-toplevel`）。**一旦识别出在 linked worktree 中，立刻读取 `references/worktree.md`**，后续按其全量处理与止步规则执行。
- 识别本次口令边界：
  1. 「提交吧」「推送」→ 只做清理、沉淀、提交，以及（主工作区下）推送当前分支；停在非默认分支时**不合并、不删分支**。
  1. 「收尾」「合并分支」→ 主工作区下额外执行合并回默认分支并安全删除当前分支。
- 默认分支优先取 `git symbolic-ref --short refs/remotes/origin/HEAD`（去掉 `origin/` 前缀）；拿不到时查本地是否存在 `main` 或 `master`，仅有一个则用之，都有或都没有时按 `~/.dsh/AGENTS.md` 核心原则 9 用 `ask_user_question` 确认，不盲猜。

## 清理

删除过期、过时、临时文件（临时脚本、探针残留、调试输出、一次性产物）。仍被引用的文件不动；`docs/plans/` 的去留由用户决定；仍被现役入口引用的 `docs/migration-*.md` 不动；拿不准是否过期的报告并保留，不擅自删。

## 沉淀

把会话里**亲手挣来、以后还会用到**的知识落进仓库或记忆；没有就跳过，不为「完整」硬凑。

**四条判据全满足才动手**：① 本次会话验证或调研得出；② 代码、测试、配置与既有文档里都没有；③ 下个会话还用得上；④ 结论能泛化为规律、契约或因果，而非某次操作的细节。

- **文档落点与门禁**：动文档前加载 `doc-governance`。仓库级每条任务都成立的规则进 `AGENTS.md`，只在特定任务成立的细则下沉 `<仓库>/.agents/skills/`（见 `~/.dsh/AGENTS.md`）；指南与调研进对应 `docs/`；术语进同级 `CONTEXT.md`；产品用法进 `README.md`。已有同主题文档就地改写，不建第二份副本。
- **决策记忆**：动记忆前加载 `decision-memory`（仅系统骨架变更且能指名被否方案时写）。
- 例行进展与一次性调试流水不沉淀；拿不准的列进报告并保留。沉淀改动并入「提交」一节按主题提交。

## 提交

- 先用 `git status` 和 diff 摸清变更。主工作区下**分清哪些属于本次会话**，其余并发会话的改动原样保留；linked worktree 下的归属规则见 `references/worktree.md`。
- **按功能主题拆成多个小提交**，**显式指定路径暂存**，禁止 `git add -A`／`git add .`。
- 提交信息用英语，说明为什么改而不只是改了什么。无待提交变更时不造空提交，直接进入下一节。

## 推送与合流

- **在 linked worktree 中到此为止**（不推送、不合并、不移除 worktree、不删分支），详见 `references/worktree.md`。
- **在主工作区**：
  1. 同步远端：当前分支落后远端时在提交后执行 `git pull --rebase`。
  1. 若口令为「提交吧」「推送」，或当前分支本身就是默认分支：推送当前分支即止。
  1. 若口令为「收尾」「合并分支」且当前停在非默认分支：先推送当前分支；再用 `git worktree list` 检查默认分支是否已检出在某个目录——若已检出，先校验该目录 `git status` 必须干净（脏则停止报告，不污染他人改动），再在该目录 `git pull --rebase` 并合并当前分支；若默认分支未检出在任何 worktree，在主工作区确认干净后 `git checkout <默认分支>`、`git pull --rebase` 并合并当前分支。
  1. 冲突就地解决后推送默认分支。
  1. 安全删除已合并分支：本地用小写 `git branch -d <分支>`（保留 Git 未合并校验，若拒删立即停止排查，禁止改用 `-D` 强删）；远端仅在确有该分支时执行 `git push origin --delete <分支>`。主工作区合流不移除任何 worktree。
- 冲突无法解决或推送被拒（权限、保护分支、网络）：立即停止并报告原因，不自行变通、不反复重试。

## 报告

列出：清理清单、沉淀清单（无则简明带过，拿不准而保留的列出）、提交清单（hash + 主题）、推送与分支处理结果（worktree 下注明需用户显式输入 `/wrap-up-worktree` 完成合流与拆除）。全程无变更才报「无变更」。

## 边界

- 涉及发布（`npm publish`、打 tag、触发发布流水线）须先确认明确授权；本技能默认不含发布。
