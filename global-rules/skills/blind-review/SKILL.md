# 双盲审与辩论

「双盲」指 Root（第一席）与一个独立子代理（第二席）在互不见对方结论的前提下各审一遍。席位职责是**判断交付物是否合格**，不扩写范围、不顺手重构；若用户只是随口询问小片段有无明显问题且未要求双盲审，直接做轻量审查，不必强套完整流程。

## 冻结审查包

把审查对象收敛为明确的路径或索引（文件清单、diff、提交号），记录版本标识（commit hash 或文件 hash）作为共同基准。两席默认按**双轴分栏**输出发现：

- **规格轴（Spec）**：是否满足需求契约、边界条件、数据与状态一致性、回归或安全风险。
- **规范轴（Standards）**：代码坏味道、浅模块与透传废层、重复或冲突、项目硬门禁与可维护性。

用户另指定维度时以用户维度为准。审查包 = 路径／索引 + 版本标识 + 双轴（或用户指定）维度 + 只读约束。发给第二席的内容**严禁夹带**背景推测、可疑点、修复方向或 Root 结论。

## 并行双盲（冻结期只审不改）

冻结审查包后，**先派出第二席子代理**，同时 Root 在**查看第二席回报之前**完成第一席自审并把条目落纸——盲性与串行完全等价，同时省去等待墙钟时间。

审查期间**严禁修改工作区**，否则两席失去共同基准、双盲作废。

- **第二席必须换模型族**：先用 `list_subagent_models` 查询可用模型（按 provider 查），选择与当前 Root **不同模型族**的高推理可用模型（例如 Root 为 Gemini 族则选 DeepSeek／Claude／GPT 等异族，反之亦然；不写死具体版本号）。双盲的收益来自盲区不重叠，绝不用与 Root 相同的路由凑数。
- 授权标记与只读硬门禁见 `collaboration-and-delegation` 技能及其 `references/delegation-markers.md`。

## 第二席验收与失败处理

- **有效产出**：必须是带 `文件:行号` 证据的发现条目；「经审查无缺陷」是有效结论。
- **派单调用报错**（无子代理 id）：核对路由参数或更换另一可用异族模型重试一次；仍不可用或无异族模型可选时，停止盲审并如实报告「本次仅单席审查」。
- **已起席位报错或返回空白**：按 `collaboration-and-delegation` 用 `send_message` 向同一席位重试一次；仍失败则终止第二席，如实报告「本次仅单席审查」。
- **越权改动工作区**：该次审查作废；先核验并恢复冻结审查包未被污染，再**新开**一个异族只读席位重审一次；再越权则停止评审，按 `~/.dsh/AGENTS.md` 核心原则 9 调用 `ask_user_question` 呈报异常请求用户裁定。

## 合并与同源判定

把两席条目按**规格轴**与**规范轴**分别对齐成表，标注来源：**Root 独有／子代理独有／共指**。子代理的独有发现须经 Root 用一手源码或命令复验后再采纳，不轻信二手结论。

- 独有条目不因另一席未提而降权。
- 两席指向同一处证据（同文件同行、同断言）且判定一致时判为**同源**；全部条目同源且全部采纳时，直接跳过辩论进入「交付与留痕」。

## 辩论收敛

先分诊：

- **规格轴**缺陷与阻断性规范违规（破坏硬门禁、引发维护事故）进入辩论与采纳流程。
- 非阻断性的**规范轴**风格建议，以及不影响默认配置／默认路径且不改动已冻结验收契约的条目，判「已知边界／非阻断建议」直接结案，不修也不辩论。

凡判「不采纳」或「部分采纳」，必须再开一轮：向第二席提交原判、Root 的反驳与证据、以及它当时未见的事实；席位逐条答「让步」或「坚持 + 具体证据」，无证据的坚持一律视为让步。

全部条目处于「采纳」或「让步」即收敛。若仍有证据支撑的「坚持」，判为**共识破裂**——立即停止继续开轮，按 `~/.dsh/AGENTS.md` 核心原则 9 调用 `ask_user_question` 呈报双方证据请用户裁定，Root 不得单方面拍板。

## 交付与留痕

- **默认只读交付**：输出评审结论、逐条裁定、辩论轮次与建议修复清单，**不擅自修改文件**。仅当用户明确授权「审查并修复」时，才在辩论收敛后统一修正缺陷并复核。
- **评审记录**：包含自审发现、盲审条目数、逐条裁定与辩论结果（零缺陷或全盘采纳时简列即可）。默认写进回复正文；审查对象是 `docs/plans/` 下的计划文档时，就地写入该文档。禁止新建独立审计文件或把评审记录塞进规则文件。
- 被放弃的架构方案与理由另按 `decision-memory` 技能记入 OpenViking，两者互不替代。

## 边界

- 只在用户显式要求审查时触发，绝不自动触发。
- 双盲审**不替代**按风险属性触发的「高风险审查」（见 `delivery-discipline`）。
- 常规实现改动未触发双盲审时，仍按 `delivery-discipline` 的「自审」一节就地修正，不适用本技能冻结规则。
