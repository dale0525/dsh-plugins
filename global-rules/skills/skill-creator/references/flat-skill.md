# 单层技能写法细则

确定做成单层技能（绝大多数技能均属此类）时读；常驻原则与规模信号见上层 `SKILL.md`，此处不重复。

## 目录结构

```
<name>/
├── SKILL.md          # 必需：触发后整份进上下文
├── references/       # 可选：特定情形才读的细则或参考表
├── scripts/          # 可选：确定性可执行脚本
└── assets/           # 可选：产出物需原样复制的模板或静态资源
```

只建真正需要的子目录；不留空目录与占位文件。

## 正文组织与写法

- 正文讲**怎么做**，不再重复 `description` 里已经写过的「什么时候用」。
- 常见结构：目标与边界 → 按顺序排列的步骤或硬门禁 → 停止条件与验收检查 → 下沉文件的相对路径与读取时机。
- **用祈使句**：写「先读 X 再改 Y」，删掉「本技能旨在帮助……」类铺垫，确保每句话都能改变执行行为。
- **产物落点写全相对路径**：不要只写「写入 CONTEXT.md」，要写清放仓库根还是模块根。
- **标题不写序号，正文不用数字引用章节**（见 `doc-governance`）。

## 何时拆资源

| 资源 | 判据 |
| --- | --- |
| `references/` | 细节量大且仅在部分情形需要；按主题分文件，正文只留导航与读取时机 |
| `scripts/` | 同一逻辑反复手写或要求确定性输出（解析、校验、生成）；脚本写完须实跑验证 |
| `assets/` | 产物需原样复制的模板、图标、样例文件 |
