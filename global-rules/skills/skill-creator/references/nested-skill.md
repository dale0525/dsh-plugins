# 嵌套（编排式）技能写法细则

仅在以下**三条同时成立**时才建嵌套技能，否则一律用单层形态（`references/flat-skill.md`）：

1. 子流程各自能独立成篇、单独读得懂；
1. 顶层确实需要按阶段做路由，不是简单清单罗列；
1. 套件内存在真正共享的 `references/` 或 `scripts/`，合在一起能避免复制。

## 目录结构

```
<name>/
├── SKILL.md              # 顶层：触发入口 + 路由表 + 共用约定
├── subskills/            # 子流程目录
│   ├── <child-a>/SKILL.md
│   └── <child-b>/SKILL.md
├── references/           # 整套件共享资料
├── scripts/              # 整套件共享脚本
└── assets/               # 可选
```

## 运行时机制

- **`subskills/*/SKILL.md` 不会被注册为独立技能**，既不进 `<available_skills>`，也不能用 `skill` 工具按名加载，更不可能「自动触发」。
- 子技能本质是普通按需读取文件，**顶层 `SKILL.md` 的路由表是唯一入口**。
- 子技能 frontmatter 不参与宿主注册，但建议保留简洁的 `name` 与 `description`，便于阅读或日后独立升格。

## 顶层与子技能分工

- **顶层 `SKILL.md` 只写路由与共用约定**：套件范围与边界 → 阶段到子技能路径的路由表（每行路径与磁盘严格一一对应）→ 共用门禁。不含任何单条子流程的细则。
- **子技能只写本阶段特有步骤**：明确输入、产物落点（全路径）与停止条件；绝不复制顶层已有规则。引用共享资源统一用相对路径 `../../references/xxx.md` 或 `../../scripts/xxx.py`（禁止自指软链接，防止遍历死循环）。
- 按需加载判据在子技能内继续生效：只在更窄分支才用得上的细节继续下沉到 `../../references/`。
