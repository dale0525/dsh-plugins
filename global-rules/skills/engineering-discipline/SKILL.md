# 工程纪律

## 环境与约定

- 代码用英语。
- 环境与工具链硬门禁见 `~/.dsh/AGENTS.md`「环境与工具链」一节，本技能不重复。
- Git 作者遵循本机 `~/.gitconfig` 或仓库本地配置，不硬编码覆盖。
- 凭据明文存储须明确落点路径并确认不被纳入版本追踪。

## 反防御性编程（硬门禁）

禁止：

- 捕获不可能发生的异常。
- 为内部调用校验参数。
- 吞异常返回默认值或降级。
- 为未确认需求预留钩子、配置或接口。
- 为内部不变量补运行时断言。
- 给私有函数写发散性边界测试。

例外（须在改动说明写明）：用户输入、外部 API、文件系统、网络、并发等真实不可信边界；用户明确要求；已发生故障的复现测试。

## 反无关工作（硬门禁）

- 只做达成验收判据所需的最小改动，范围外发现只报告不修改。
- 注释禁止装饰性与显而易见的描述；允许记录「代码本身看不出来、又不适合进文档」的非显然因果，并在改动说明指明该因果。
- 按需加载的技能所定义的流程性产出（文档治理、盲审记录、记忆写入）只在触发命中时执行，未触发即零产出，不为「合规完整」补做。

## 事实与因果分离

- 第一真源是代码、测试与配置；文档禁止手抄代码事实（边界见 `doc-governance`）。
- 找理由只有三个去处：`docs/plans/`（事前冻结）、OpenViking（事后因果，见 `decision-memory`）、代码注释（仅限代码内可见、进文档不划算的因果）。

## 验证广度上限

- 为一次改动追查调用链最多三层：当前函数 → 直接调用方 → 该调用方的入口；超出即改为写代码或跑命令验证。
- 跨四个以上文件才能确定的因果，先写最小复现再回来。

## 测试先行

- 验收契约冻结并进入写代码阶段时，必须测试先行；**不因改动行数少而豁免**。
- 只写验证当前契约的针对性测试；禁止形态见「反防御性编程」一节。
- **确保测试真能抓缺陷**：
  1. 严格测试先行时，以「实现前跑红 → 实现后跑绿」作为真红真绿证据，不必再把实现改回缺陷版二次复测。
  1. **后补测试（实现早于测试）或怀疑假测试时**，必须临时把实现改回缺陷版确认该测试变红后再恢复。
  1. 警惕两类假测试：断言恒真（断言格式与源码无关）；测试里复写了一遍源码算法导致只测复制品。优先测公共接口；确有复杂私有逻辑无法通过公共接口覆盖时，仅抽最小必要纯函数，不无故扩大导出面。
- 豁免：文档、纯提示词／文案调整、无逻辑分支的配置开关、一次性脚本、探索性 spike、以及不存在可冻结长期契约的改动不适用测试先行，改为交付前实跑一次并附命令输出为证。

## 激进清理

- 重构、替换、迁移后，新版本是唯一事实来源；本次重构产生的旧代码、垫片、别名、标志、遗留标识符、过时注释、旧测试与旧文档一律彻底删除，属重构本身不需额外授权。
- 无关的既有死代码仍只报告不修改。
- 验收：在目标范围内搜索旧标识符无遗留痕迹。
- 豁免仍被现役入口引用的 `docs/migration-*.md`；`docs/plans/` 去留由用户决定。
- 未获授权禁止重写 Git 历史。

## 界面验证

- 面向用户的界面改动用真实界面自动化工具验证，工具选择与前置加载见 `interface-operations`。

## 提交与推送

- 仅当项目由 Git 管理且用户显式要求提交／推送／收尾时执行，未要求绝不碰 Git；流程见 `wrap-up`。
