# 派单授权标记与硬门禁

只在需要派子代理、尤其是要授予 `[审核]` 或 `[编辑: <路径>]` 权限时读。

`@logictan/dsh-force-rules` 根据 `prompt` 开头标记控制席位工具白名单：`[只读]`（读文件、检索、联网、回报，含各 MCP/ssh 服务的只读工具）、`[审核]`（追加只读命令）、`[编辑: <路径>]`（**同样的只读命令** + 仅写所列文件或目录）。

## 标记位置与静默降级

- **必须开在 `prompt` 最前面**（仅允许前导空白）。标记前出现任何正文文字都会失效，席位**静默降为只读**且派单时不报错，直到写文件被拒才暴露。
- 若要在正文中提及规则写法，放到开头标记之后或去掉方括号，避免混淆。

## 授权路径匹配规则

门禁按路径后缀比对，所以相对路径、`./` 前缀与绝对路径都能匹配同一个文件：

- **优先写仓库相对路径**（如 `packages/foo/src/a.ts`）：席位用相对、`./` 或绝对路径都能匹配通过。
- **避免写绝对路径**：授权写绝对路径时，席位改用相对路径会被拒绝。
- **写目录即授权其下全部文件**：`[编辑: /tmp/x/]` 或 `[编辑: packages/foo/]` 允许写该目录下任意文件，不必逐个列出。目录内的文件路径要全部列出时也可以，两种写法都行。

## 只读命令的边界（`[审核]` 与 `[编辑]` 都适用）

- **逐段校验**：`git status --porcelain | head`、`cd repo && ls && wc -l file` 这类只读组合放行；只要有一段不是只读命令，整行拒绝。
- **写标志仍拒绝**：`find -delete`、`find -exec`、`sed -i`、`curl -o`、`awk` 里的 `system()`、`$()`、反引号、真会写文件的重定向一律拒绝。`2>&1` 与 `> /dev/null` 不算重定向。
- **跑测试、构建、提交仍要由派单方自己做**：这些不在只读命令集里。

## 其余运行硬约束

- **派发深度上限为 1**：子代理不能再调用 `subagent`，多层拆解由 Root 一次性拆完后分派。
- **无 `run_in_background` 参数**：`subagent` 与 `subagent_fork` 默认后台异步运行且可持续对话，不要传入 `run_in_background`。
- **自唤醒检查点由插件自动管理**：席位启动即登记检查点，结算自动撤销，不需要手工定时或轮询；具体超时常量以 `@logictan/dsh-force-rules` 插件实现为准。
