# 派单授权标记与硬门禁

只在需要派子代理、尤其是要授予 `[审核]` 或 `[编辑: <路径>]` 权限时读。

`@logictan/dsh-force-rules` 根据 `prompt` 开头标记控制席位工具白名单：`[只读]`（读文件、检索、联网、回报）、`[审核]`（追加只读命令）、`[编辑: <路径>]`（追加仅写所列文件）。

## 标记位置与静默降级

- **必须开在 `prompt` 最前面**（仅允许前导空白）。标记前出现任何正文文字都会失效，席位**静默降为只读**且派单时不报错，直到写文件被拒才暴露。
- 若要在正文中提及规则写法，放到开头标记之后或去掉方括号，避免混淆。

## 授权路径匹配规则

门禁只校验 `候选路径 === 授权项` 或 `候选路径.endsWith('/' + 授权项)`（单向后缀包含）：

- **优先写仓库相对路径**（如 `packages/foo/src/a.ts`）：席位用相对、`./` 或绝对路径都能匹配通过。
- **避免写绝对路径**：授权写绝对路径时，席位改用相对路径会被拒绝。
- **目录不递归授权其下文件**：`[编辑: /tmp/x/]` 仅匹配目录本身，要写 `/tmp/x/a.md` 必须逐个列出具体文件路径。

## 其余运行硬约束

- **派发深度上限为 1**：子代理不能再调用 `subagent`，多层拆解由 Root 一次性拆完后分派。
- **无 `run_in_background` 参数**：`subagent` 与 `subagent_fork` 默认后台异步运行且可持续对话，不要传入 `run_in_background`。
- **自唤醒检查点由插件自动管理**：席位启动即登记检查点，结算自动撤销，不需要手工定时或轮询；具体超时常量以 `@logictan/dsh-force-rules` 插件实现为准。
