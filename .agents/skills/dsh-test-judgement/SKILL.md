# 测试失败的归属判据

本仓库没有 CI 门禁，测试由人在本地跑。因此「这条红是不是我造成的」必须靠判据回答，**不能靠再跑一遍**。四条门禁命令见 `AGENTS.md` 的「✅ 验证命令」。

## 五条归属判据

- **偶发失败只能靠「改动前后同次数对比」判定**：单次复跑通过说明不了任何事。把改动 stash 掉，在干净 HEAD 上以**同样的次数**跑同一文件，比较失败次数；相等即既有问题。
- **并发配对会让「与本次改动无关」的包失败**：`--workspace-concurrency=2` 每次挑两个包同跑，挑谁取决于工作区里有哪些包。先 `git diff <base> -- <该包>/` 确认未改，再看并发限 1 是否转绿。**别调大并发**——它是给 jsdom 留 CPU 的。
- **本地完整克隆会让 `pnpm test` 红，而 CI 浅克隆绿**：判据是 `sync-upstream.mjs --preflight` 的输出，不是测试本身。
- **时钟取样的断言必须注入 `now`**：否则红绿由机器速度决定（实测同毫秒概率约 27%）。
- **平台分支代码本地全绿不代表正确**：Linux 分支在 macOS 上完全不走，必须让 CI 在 ubuntu 上跑过一次。
