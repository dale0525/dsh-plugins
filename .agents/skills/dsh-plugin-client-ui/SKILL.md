# 客户端 UI：槽位、注入与 DOM

客户端半边没有编译期约束，错误只体现在页面上（空白、错位、样式不生效）。

## 六条硬门禁

- **`<style>` 注入不能写成「已存在就跳过」**：客户端 HMR 替换的是插件 fiber，不重跑启动逻辑，「已存在就跳过」会让新 CSS 永远注不进页面。每次激活都重写已有标签的 `textContent`。
- **替换宿主渲染的元素只能用纯 CSS**：宿主元素带 `__reactFiber$*`，React 会按自己的 fiber 调和回去，任何 DOM 手术都只是临时的。做法是藏掉宿主元素 + 在父级用伪元素重画。
- **拦截宿主 RPC 只能在 head 注入里做**：RPC 传输层在模块初始化时就绑定了 `globalThis.fetch`，插件侧再包一层永远看不到那次调用。位置是 `webserver/index-inject` 的 `kind: 'script'` + `placement: 'head'`。
- **同一个 `Menu` 原语渲染出的两个座位只能靠 `[data-slot]` 区分**，形状认不出来——按形状找菜单会命中别人的。
- **槽位渲染崩溃在页面上是「空的」**：宿主把它换成无文案的 `data-slot-error` 元素，诊断只能去控制台取原始 Error，对着 DOM 猜永远猜不到。
- **别往侧边栏会话行的 `leading` 槽位常驻图标**：那一格空着才是缩进的来源，塞进去就抹掉了层级。
